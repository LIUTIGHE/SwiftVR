# M11B-S1-D0 — Decoder phase bias diagnostics

This is the first implementation node of the M11B two-stage quality roadmap.

**Scope:** diagnose **already rendered** M11-B 30k + M9-A1 vs the **same M11-B 30k + Original ReAE decoder**. Separately inspect the local two-phase kernels of both decoders' temporal TGrow blocks. No training, no overwrite of prior experiments, no claims of GPU/visual pass.

**Source models (immutable):**
- M11-B: verify the **exact checkpoint used for both renders**. The Wetland1 `complete.json` received on 2026-10-20 identifies `outputs/b2b/m11b_stagea_ultra_bootstrap30k_v1/checkpoints/step_00030000`, while earlier commands used `outputs/b2b/m11b_stagea_ultra_30k_v1/checkpoints/step_00030000`. Do not assume they have identical weights: compare SHA256 of the two `transformer/diffusion_pytorch_model.safetensors` files (if both exist) and check the Original-decoder inference log before making same-latent decoder attribution.
- Original ReAE: `checkpoints_prompt_free_no_time/reae.safetensors`
- A1 E99: `outputs/b2b/m9a1_factorized_m8a30k/checkpoints/epoch_099_step_00024552/tiny_decoder/model.safetensors`

All **new** results go under `outputs/m11b/M11B-S1-D0/`.

## 1. Frames: no GPU needed

The two input PNG folders **must** have been produced from the same physical video file, same starting frame, same full-input origin, same M11-B 30k Transformer, C24 streaming, 3x resolution, zero DiT overlap. Only the decoder differs.

```bash
cd /data1/a/SwiftVR

A1_PNG=outputs/custom/m11b_30k/Wetland1/png
ORIGINAL_PNG=outputs/custom/m11b_30k_original_decoder/Wetland1/png

test -d "$A1_PNG" && test -d "$ORIGINAL_PNG"

python tools/m11b_s1_d0.py frames \
  --a1 "$A1_PNG" \
  --original "$ORIGINAL_PNG" \
  --start 221 --end 253 \
  --roi 960,540,960,960 \
  --snapshots 245,248 \
  --output-dir outputs/m11b/M11B-S1-D0/Wetland1_221_253
```

**Do not** re-cut at input frame 221: that changes the encoder/decoder's four-phase origin. The code uses output ordinal `(t+3)%4`, hence output frame 245 is phase0, 248 is phase3 **only for the original input origin**. It checks source PNG filenames and counts, but cannot cryptographically prove two folders were generated from identical input/model settings. Check the old inference logs and commands.

### If only `native_frame_*.png` montage snapshots remain

The historical validation script defaults to `KEEP_CUSTOM_PNG=0`, deleting complete `current_png` sequences **after** rendering the full lossless `native_fourway.mkv`. The sampled `native_frame_*.png` images are NOT valid phase-diagnostic input.

First locate the matching video and inspect its `complete.json` provenance:

```bash
find outputs/custom outputs/m11b -type f -name native_fourway.mkv 2>/dev/null | grep Wetland1
```

Only if that FFV1 video belongs to **M11-B 30k + A1**, extract its lower-left **Current** panel. The historic 960x960 ROI has a 28px title band in each 988px-tall cell; Current RGB starts at `x=0,y=1016`. The upper-right **Original SwiftVR** panel is NOT the M11-B + Original Decoder reference.

```bash
FOURWAY=outputs/custom/m11b_30k_visual/Wetland1/native_fourway.mkv  # replace with ACTUAL path
EXTRACT=outputs/m11b/M11B-S1-D0/Wetland1_A1_extracted_roi
test -f "$FOURWAY"
test ! -e "$EXTRACT"
mkdir -p "$EXTRACT"
ffmpeg -nostdin -v error -i "$FOURWAY" \
  -vf 'crop=960:960:0:1016' -vsync 0 -start_number 0 "$EXTRACT/%05d.png"
```

The **separately rendered** M11-B 30k + Original Decoder PNG sequence remains required. Because its PNGs are full-resolution, pass `--original-roi`, not the common `--roi`:

```bash
python tools/m11b_s1_d0.py frames \
  --a1 "$EXTRACT" \
  --original outputs/custom/m11b_30k_original_decoder/Wetland1/png \
  --original-roi 960,540,960,960 \
  --start 221 --end 253 --snapshots 245,248 \
  --output-dir outputs/m11b/M11B-S1-D0/Wetland1_221_253_from_montage
```

The FFV1 mosaic preserves the native ROI pixels and full frame order. The output PNG ordinal starts at **0**, with five digits (`00000.png`) to match SwiftVR's canonical `append_chunk_to_png_dir` naming. If the separately rendered Original has different naming, first inspect/normalize names without changing ordinal pairing. Verify that the input sequence, physical start, M11-B checkpoint, and C24 settings match; the tool checks frame *names and lengths*, not the provenance of separate source videos. For a different recorded ROI, derive the extraction rectangle from its `complete.json` and source script instead of hardcoding `960` and `1016`.

If there is **no complete FFV1 video**, the sparse `native_frame_*.png` snapshots alone are insufficient. Regenerate only the M11-B + A1 PNGs using `scripts/inference_custom_components.py --png` on the full, original video from the same starting frame and write to a fresh `outputs/m11b/M11B-S1-D0/...` path. Use the separately rendered M11-B + Original Decoder output as the other source; do not substitute Original SwiftVR.

Some historic `visual_check_m8_task.sh validate` runs delete their temporary `current_png` frames after composing FFV1 (`KEEP_CUSTOM_PNG=0` by default). If the A1 PNG folder no longer exists, regenerate it **once** from the original entire input with `scripts/inference_custom_components.py`, not from a 221-frame crop. Use an output path unique to this experiment, such as `outputs/m11b/M11B-S1-D0/Wetland1_A1_input_replay/png`, then pass that path to `--a1`. The Original render can be reused if still available.

Output:
- `frames.csv`: per-frame phase, low-frequency luminance and high-frequency discrepancy, optionally GT measurements.
- `summary.json`: mean by phase and a four-sample DFT over phase-conditioned luminance discrepancy.
- `native_roi_000245_p0.png`, `native_roi_000248_p3.png`: native-resolution, same-ROI side-by-side snapshots if indices are in range.

Optionally use `--gt /path/to/strictly-aligned-3x-HR-PNG` for GT-relative errors. Custom Wetland1 does not automatically have paired 3x HR; do **not** substitute interpolated LQ or an unrelated frame bank as GT. Without GT, disagreement between A1 and Original is **not** an absolute quality metric.

For a second video use a **fresh** output folder under `outputs/m11b/M11B-S1-D0/Mangrove1_...`. When changing scene, use the **identical frame origin for both decoders**.

## 2. TGrow: CPU-only safetensors weight analysis

```bash
python tools/m11b_s1_d0.py tgrow \
  --reae checkpoints_prompt_free_no_time/reae.safetensors \
  --a1-model outputs/b2b/m9a1_factorized_m8a30k/checkpoints/epoch_099_step_00024552/tiny_decoder/model.safetensors \
  --output-dir outputs/m11b/M11B-S1-D0/tgrow_kernel
```

For each of two stride-2 TGrow layers, time replication of one latent sample `z` yields two local outputs with effective maps `(W_mid+W_right)z` and `(W_left+W_mid)z` under the real k=3, padding=1 temporal convolution. Report relative Frobenius gap and constant-channel DC response gap. This is **only a local kernel property** and does not isolate the behavior of multiple TGrow layers combined with intervening MemBlocks or the M11-B latent distribution. Asymmetry alone does **not** establish phase flicker causality.

## 3. Tests and interpretation

```bash
python -m unittest tests.test_m11b_s1_d0 -v
```

If the server's test naming layout does not make `tests` importable, use `python -m unittest discover -s tests -p 'test_m11b_s1_d0.py' -v`.

Interpretation checklist:
- Compare A1/Original discrepancy **per phase**, particularly 0 vs 3; do not use raw HF energy as a quality score.
- If GT is available, check per-phase LF/HF errors **against GT** for both outputs.
- Compare the structure of weight response discrepancies with the real-frame phase pattern; neither alone proves the other causes it.
- A1 E99 whole-clip versus streaming **was not proven exact** by historical D0: old D0 tested Original and Decoder76, not this current A1 configuration.
- These reports are diagnostics, not inference timing benchmarks or temporal-motion compensated flicker scores.
