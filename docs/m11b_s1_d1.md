Purpose: produce an immutable `z_sr = z_lq - v_M11B` for exactly the canonical paired LR/GT training views, so the next `M11B-S1-T1` can freeze M11-B and optimize only the A1 decoder. This tool is NOT a training script, and does not render/copy full HR targets or precompute the Original Decoder teacher RGB.

## Implementation

`tools/m11b_s1_d1_cache.py` builds a separate cache per domain. The source views are the same canonical deterministic ones previously used by P1:

- Legacy: `build_legacy_pairs` using original Stage-A teacher-cache **metadata for view identity only**. Stage-A velocity tensors are not read.
- UltraVideo: `build_ultra_pairs` using the canonical materialized HR paired manifests; each view's `lr_row_sha256` is checked against the LR manifest.

The script uses `prepare_training_batch` to **bilinearly resize LR to HR output geometry before ReAE encoding**; this matches the inference/training protocol. The pixel target is not fed as model input. Each sample's `z_sr` is stored as float16 [F,48,h,w] in safetensors, with manifest fields `pair_id`, domain, source index, expected LR/GT shapes and latent shape.

The immutable `plan.json` hashes the base ReAE, M11-B transformer config + weights and source view/HR manifests. If interrupted, `--resume` verifies the exact plan, verifies completed latent files and skips only valid results; each new sample is atomically renamed into place. `metadata.json` is published only after all selected samples finish. Existing training checkpoints are never modified.

A limited pilot is a **distinct cache** from formal full-data materialization; do not mix them.

## 1. Legacy 4-view GPU smoke (new directory)

```bash
export CUDA_VISIBLE_DEVICES=7
CKPT=outputs/b2b/m11b_stagea_ultra_bootstrap30k_v1/checkpoints/step_00030000

python tools/m11b_s1_d1_cache.py \
  --domain legacy \
  --base-checkpoint checkpoints_prompt_free_no_time \
  --source-checkpoint "$CKPT" \
  --legacy-view-cache outputs/b2a/cache_stage_a200k_train_full \
```

## Interpretation and next hand-off

- D1 cache represents **training-view latents**, not a C24 full-video streaming trace. Long-video validation remains necessary in T1.
- `pair_id` identifies the exact LR/HR pair. T1 must independently reconstruct its dataset and verify matching `pair_id` and hashes before using a cache record.
- Original Decoder RGB teacher will be computed from **the same frozen z_SR** in T1; use GT low-frequency/temporal constraints to avoid inheriting Original's two-frame luminance flicker.
- The original A1 E99 is an initialization, not yet a Phase-Stable Decoder.
- Code submitted to PR #4 does **not** claim server GPU tests or visual success.

After successful Legacy + Ultra smoke, the next task is `M11B-S1-T1`: DDP decoder-only refinement with full source identity checks, GT + teacher RGB + phase-aware / flicker losses and explicit per-phase long-video gates.
