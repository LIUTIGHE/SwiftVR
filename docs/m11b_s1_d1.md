## Implementation

`tools/m11b_s1_d1_cache.py` builds a separate cache per domain. The source views are the same canonical deterministic ones previously used by P1:

- Legacy: `build_legacy_pairs` using original Stage-A teacher-cache **metadata for view identity only**. Stage-A velocity tensors are not read.
- UltraVideo: `build_ultra_pairs` using the canonical materialized HR paired manifests; each view's `lr_row_sha256` is checked against the LR manifest.

The script uses `prepare_training_batch` to **bilinearly resize LR to HR output geometry before ReAE encoding**; this matches the inference/training protocol. The pixel target is not fed as model input. Each sample's `z_sr` is stored as float16 [F,48,h,w] in safetensors, with manifest fields `pair_id`, domain, source index, expected LR/GT shapes and latent shape.

The immutable `plan.json` hashes the base ReAE, M11-B transformer config + weights and source view/HR manifests. If interrupted, `--resume` verifies the exact plan, verifies completed latent files and skips only valid results; each new sample is atomically renamed into place. `metadata.json` is published only after all selected samples finish. Existing training checkpoints are never modified.

A limited pilot is a **distinct cache** from formal full-data materialization; do not mix them.

## Exact full-cache shell commands (after smoke PASS)

All outputs below are fresh, separate directories under `outputs/m11b/`; do not use `--max-samples` for formal caches. Before starting confirm free disk via `df -h outputs`. A float16 4x48x24x24 latent costs ~216 KiB per view before file-system overhead; a full ~16k Legacy plus ~20k Ultra cache would use roughly 7.5 GiB for latent payloads, **in addition** to preexisting HR/LR bundles, logs and metadata. Train-view cache generation repeatedly reads paired HR (already materialized), so substantial disk I/O is expected.

# Legacy training views (all 15896 if the historical metadata is unchanged).

  --domain legacy --base-checkpoint "$BASE" --source-checkpoint "$CKPT" \\
  --legacy-view-cache outputs/b2a/cache_stage_a200k_train_full \\

  --batch-size 1 --num-workers 2 --dtype bfloat16 \\

For the full UltraVideo HR shard manifests, fail closed if the expected four are absent or a different number is found:

```bash
HR_ROOT=outputs/data_audit/ultravideo_hr_train_v1
mapfile -t ULTRA_PAIRS < <(find "$HR_ROOT" -mindepth 2 -maxdepth 2 -name paired_views.jsonl -type f | sort)
printf '%s\\n' "${ULTRA_PAIRS[@]}"
if [ "${#ULTRA_PAIRS[@]}" -ne 4 ]; then
  echo 'ERROR: Expected four complete paired-HR shard manifests; stop.' >&2
else
  ULTRA_ARGS=()
  for path in "${ULTRA_PAIRS[@]}"; do ULTRA_ARGS+=(--ultra-pairs "$path"); done
  python tools/m11b_s1_d1_cache.py \\
    --domain ultra --base-checkpoint "$BASE" --source-checkpoint "$CKPT" \\
    "${ULTRA_ARGS[@]}" \\
    --batch-size 1 --num-workers 2 --dtype bfloat16 \\
    --output-dir outputs/m11b/M11B-S1-D1/ultra_train_full
fi
```
