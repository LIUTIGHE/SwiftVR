## 1. Objective

`swiftvr/training/m11b_phase_objective.py` supplies:

```
L = w_gt * L1(A1, GT)
  + w_teacher * L1(A1, OriginalDecoder(z_SR))
  + w_HF * L1(HP(A1), HP(GT))
  + w_LFtime * L1(temporal_diff(LP(Y(A1)-Y(GT))))
  + w_phase * (smoothmax(per_phase_GT_HF_errors)-mean(per_phase_GT_HF_errors))
  + w_LPIPS * LPIPS(A1,GT)
```

- GT constrains real brightness/structure/detail and time variation.
- The Original Decoder on **the same frozen M11-B latent** is an appearance teacher only; no teacher-temporal flicker target.
- HF objective compares **per-frame output against per-frame HR**. It does not equalize the frequency content of unrelated motion frames.
- LPIPS uses existing fully local AlexNet weights, fails closed if unavailable; no implicit download.
- Internal phase labeling for a full 13-frame clip is `(t+3)%4`. This does not establish long-video cross-chunk quality.

Default weights are *pilot hyperparameters*, not claimed as validated.

### Root-cause status and decision

- Val13 step0→500 improves GT PSNR 24.783→26.244dB, LPIPS .3138→.2777 and GT-HF L1 .01823→.01653, but T1 increases Original-Teacher L1 .01126→.02390. This is an observed **distortion/perception-generalization tradeoff**, not proof that GT metrics are erroneous.
- Default step500 weighted loss terms (roughly): GT pixel L1 .02825, GT LPIPS .02777, GT-LF temporal .01063, Original Teacher L1 .00597, GT HF L1 .00165, phase balance ~.000010. Absolute loss magnitudes do not directly determine gradient dominance. The present phase-balance objective measures *imbalance of GT-HF errors*, not preservation of useful high-frequency energy; reducing all phases may also reduce measured phase disparities.
- Training steps are limited: 500 updates × effective batch8 = 4,000 sample **presentations**, versus 35,984 full train views. Sampling is replacement-based/balanced, so that is not a complete epoch and a longer run might further optimize its stated GT objective. Nevertheless, existing trajectories/visible texture loss **do not justify assuming that more steps will fix the target defect**.
- T13/384×384 paired training views and C24/full-resolution custom inference are distinct execution/data regimes. Whole-clip versus actual streaming phase-state behavior remains an unresolved factor.
- **Decision: T1 pilot500 is a successful GT metric refinement but FAILS the custom-video detail-preservation gate; E99 remains the visual/reference baseline.** Preserve all checkpoints and native PNGs. Do not label T1 as phase-correction success; do not overwrite E99.

### Proposed next controlled stage: M11B-S1-T1B (proposal, not yet trained)

1. Keep frozen M11-B and fixed D1 pairs; fresh A1 E99 initialization, matching val13/custom evaluation to T1.
2. Add an explicit **texture-preservation reference** such as HF/feature-level distillation from frozen E99 on initially good phases (particularly P3), plus cautious high-frequency guidance from frozen Original ReAE on weaker phases (particularly P0). This should be content/GT reliability-aware where possible, not naive HF-energy maximization (which could amplify ringing/noise or hallucinations).
3. Avoid cloning Original ReAE luminance flicker: use high-pass/feature targets, keep GT-relative LF temporal consistency, and measure phase-separated detail **and** temporal stability.
